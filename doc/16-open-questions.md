# 16｜待决策事项、技术 Spike 与风险登记

> 本文用来避免“所有推荐技术都被当成已经验证的决定”。  
> **已定的产品边界**见 PRD；本文件强调工程上尚需实测的变量及判定方式。

## 1. P0 前必须通过的 Spike（不是无限讨论）

| ID | 问题 | 默认方案 | 最小实验 | 通过标准 |
|---|---|---|---|---|
| S-01 | 能否从真实供应商 XLSX/PDF 稳定抽取单价、币种、包装口径 | openpyxl + Docling + LLM | 每种 3 份结构不同样本，人工标签 | 关键价格误提取不会无提示进入正式计算 |
| S-02 | Canonical JSON 能否承载常用 Costing/Spec/Quotation 编辑 | Pydantic + AG Grid | 设计 2 套明显不同的箱包规格/成本结构 | 不需改底层表即可表示主要差异 |
| S-03 | 多工件变更路径是否可用小型依赖表实现 | Rules + Graph Traversal | 彩盒/LOGO/数量三种变更 | 正确标记所有已定义下游，未知关联提示 review |
| S-04 | LangGraph 审批恢复是否适合现有部署 | Persistent Checkpointer | 审批中断、Worker restart、相同 Tool 重放 | Run 可恢复，无重复写入 |
| S-05 | 无复杂 Office 引擎能否导出真实可编辑成果 | openpyxl + docx Renderer | Cost Sheet/Quotation/PI 3 模板 | 数字和格式经二次验证，无关键截断 |
| S-06 | 如何选择 LLM/VLM 模型 | Provider Adapter | 固定 20 条抽取任务对照 | 按字段正确率/时延/费用评估，不凭排行榜选 |

## 2. 需要业务访谈但不阻塞 Demo 的问题

- 报价到底由 Sales、老板、业务经理还是采购确认？小公司能否单人执行多个**内部**审批角色？
- 企业真正使用的 Tech Pack/BOM 是简单 Excel、带图片的复杂模板，还是以样品为主？
- 跟单员是否更愿意在新工作台编辑，还是更倾向在原有 Excel/邮件中调用 Agent？
- 包装、LOGO 变更后最容易漏的文件究竟有哪些，是否因企业/产品而异？
- 是否有真实匿名资料可做 Golden Dataset？没有就必须明确“全部测试为模拟资料”。
- 成本口径是否包含税、退税、手续费、模具摊销、运杂、损耗、汇率锁定？

## 3. 高优先级风险与缓解

| 风险 | 严重性 | 早期信号 | 缓解 |
|---|---|---|---|
| 做成“模板生成器” | 高 | 单次输出成功但不会跨版本修改 | Flow B / Impact + Diff 做成第一卖点 |
| 强依赖多模态抽取完美正确 | 高 | 错误价格悄然出现在报价 | Evidence + Unknown + 二次校验与人工审阅 |
| 过度设计事实库 | 高 | 没有任何可用文件，却先做庞大 Schema | 只服务三条 Flow，必要时 JSONB |
| 误把草稿接受当商业批准 | 严重 | 一键发布新报价/生产单 | Gate 独立于 Draft Apply，版本哈希绑定 |
| 复杂 Agent 失败难排查 | 高 | 多 Agent 互相推责任/重复调用 | 单 Agent + Typed Tools + Run Event |
| Office 编辑器授权/功能不符 | 中高 | Demo 需要 Enterprise Excel Export | 后端模板生成，不依赖 AG Grid 商业特性 |
| 工作台切换成本高 | 商业风险 | 用户依旧导出到 Excel 才肯编辑 | 高质量 XLSX 输出，研究嵌入式工作形态 |
| 无真实第三方系统可连接 | 中 | 依赖真实 Gmail/ERP 演示无法开始 | 先上传 / 导出，真实连接器作为 P1 |
| 解析错误来源不可定位 | 高 | 用户无法判断价格从哪来 | 强制 Source Locator 与来源预览 |

## 4. 开发阶段的决策规则

- 若任何 Spike 明显失败，先保留**稳定业务闭环**，降低格式/编辑功能覆盖，不牺牲金额与审批正确性。
- 技术选型需要记录事实：样本、成功率、失败类型、替代方案和后续影响。
- “创新性不足”是产品验证问题，不靠增加七个 Agent 或复杂图数据库解决。
- P0 的 Scope 变更要注明取消哪一个验收项，不允许 UI 假完成顶替。

## 5. 与已确定事项的边界

**已确定**：一人 AI-Native 工作台、Artifact-first、真实交付物、三条连续 Flow、人工控制高风险、上传文件优先、单主 Agent + Tools。  
**建议待验证**：具体模型/版本、Docling 对真实报价的表现、LangGraph vs 更简状态机、前端编辑器细节、对象存储部署策略、是否用 Redis。  
**延期决策**：真实邮箱发送、ERP/MES、物流、收款、完整 PLM/CRM、多人协作、自动生产进度监控。
