# EasyWork · 一人 AI-Native 包袋外贸工作台
## Hackathon PRD v0.3：设计、BOM、Office 与变更联动

**日期：2026-10-31**  
**版本关系：更新参赛分支 v0.2，不覆盖长期《完整融合 PRD V2.0》。**  
**产品范围：前五个 SOP、两个相关工作流；沿用十小时开发、三分钟演示的项目约束。**  
**本次新增：变更意图驱动的全链路联动。**  
**文档性质：产品需求，不代表功能已经实现。**

> 一个跟单员在同一个工作台完成需求理解、竞品分析、产品设计、BOM 核价、打样资料和订单文件。
>
> **客户或用户改变一个要求，Agent 主动找出所有受影响的已纳管成果，自动推进关联修改、复算、校验和文件更新，不让旧内容无提示地继续充当当前结果。**

## 0. 产品范围

### 0.1 必须保留的能力

| 能力 | 产品要求 |
| --- | --- |
| 连续业务上下文 | 询盘、设计、规格、BOM、报价、样品和 PO/PI 属于同一笔业务，后续工作复用已有成果 |
| 通用文件编辑器 | 真实编辑文档正文、表格、图片和工作表，不以固定表单或截图替代 |
| 原生文件导出 | 支持真实 XLSX、DOCX、PDF；产品模拟图可下载 |
| 竞品数据分析 | 分析少量有来源的资料，形成有依据的设计观察和建议 |
| AI 美工与生图 | 生成产品概念模拟图，编排可编辑的客户方案 |
| 简易 BOM 识别与核价 | 实际识别图片或读取 XLSX，按行核对后由程序计算成本和报价 |
| 变更全链路联动 | 客户反馈、用户指令、文件编辑或来源更新触发影响识别和关联成果更新 |
| 校验与反馈 | 发现问题、说明影响和所需补充；补充后继续同一工作，而不是重新开始 |
| 历史与来源保护 | 原始资料、旧版本和既有确认记录不被后台覆盖 |

### 0.2 不纳入本版

不新增完整 CRM、企业账号后台、多人实时协作、全网竞品采集、通用插件市场、复杂任务调度平台、多币种、多供应商自动询价或多款成品报价。

不做真实邮件发送、合同签署、付款、采购生产下达，也不扩展至生产、验货、出运、收款和售后管理。已有稳定首页和业务 Tab 可继续保留。

一个成品款号可以包含多行 BOM；保留通用编辑能力不等于承诺任意复杂 Office 文件都能无损兼容。

## 1. 产品定位与核心价值

**EasyWork 是把客户需求转成“可看、可改、可核价、可交付”，并能随变更持续保持关联一致的包袋方案与订单文件的一人 AI 工作台。**

目标用户是中小 B2B 包袋出口商的跟单员或跨岗位业务人员。用户负责目标、商业判断和必要确认；Agent 负责读取资料、分析、调用工具、制作成果及联动更新。

核心价值包括：

- **连续完成工作：**从询盘到设计、报价、打样资料及 PI，不重复输入同一份背景。
- **直接操作成果：**用户与 Agent 共用真实文档、工作表和图片，而不只是交换聊天文本。
- **一处变更，关联跟进：**自动识别所有受影响的已纳管文件；能确定的自动更新，缺依据的明确列为待确认。
- **保持交付一致：**页面和导出文件使用明确的内容版本，不把旧报价、旧图或旧 PDF 当成最新成果。

这里的“持续保持一致”不是承诺每个任务零延迟完成，而是：变更一旦进入系统，相关成果即进入更新、复核或失效状态，更新期间也不会被误标为当前有效结果。

## 2. 五个 SOP 的产品落点

| SOP | 核心动作 | 实际成果 | 责任边界 |
| --- | --- | --- | --- |
| 一、客户开发与询盘评估 | 读取已收到的询盘，整理主体、产品、数量、目标市场、价格和交期要求，提出澄清问题 | 需求简报、客户信息、待确认清单 | 不宣称已完成获客、身份核验或信用调查 |
| 二、产品需求确认 | 分析竞品，形成设计简报，生成模拟图与客户方案，识别简易 BOM，整理规格 | 竞品比较、设计简报、概念图、规格书、结构化 BOM | 图像不证明材质、精确尺寸、性能或制造可行性 |
| 三、成本核算与报价 | 核对 BOM 用量、价格与费用范围，确定性计算成本并生成客户报价 | BOM/成本工作簿、客户报价 | 未知成本不能猜；竞品售价不能作为自家成本 |
| 四、打样与确认 | 生成打样资料，关联样品版本，识别客户反馈及批准范围 | 打样指令、样品修改与确认记录 | 概念图认可不等于实际样品批准 |
| 五、订单与合同确认 | 对照 PO、规格与报价，处理差异，形成 PI 与执行前提清单 | PO 差异报告、PI 草稿、待确认条件 | 文件制作不等于签署、到账或开工 |

五个 SOP 共享一个工作环境和一条数据链，不建设五个互不关联的应用。

## 3. 两个相关工作流

### 3.1 W1：询盘 → 设计提案、BOM 核价、报价与打样资料

```text
客户询盘 + 产品资料 + 竞品资料 + BOM 图片/表格
                    ↓
            理解需求、标记未知
                    ↓
       ┌────────────┴────────────┐
       │                         │
    竞品比较                  BOM 识别/读取
       ↓                         ↓
    设计简报                  原表核对与校验
       ↓                         ↓
    AI 产品模拟图             确定性成本与报价
       │                         │
       └────────────┬────────────┘
                    ↓
         对齐同一款号、规格与方案
                    ↓
    客户提案 + 规格 + 成本 + 报价 + 打样资料
                    ↓
            编辑、校验、审阅与导出
```

两条支路可以分别推进，但必须核对设计与 BOM 的适用关系。图片生成不能替代供应商或商家的成本依据。

W1 期间出现新的需求、图像修改或 BOM 编辑，直接进入第 10 节的变更联动，不需要重建询盘。

### 3.2 W2：样品反馈 + PO → 订单核对、修订与 PI

```text
W1 已有成果 + 外部样品记录 + 客户反馈 + PO
                    ↓
       理解反馈，判断变更与确认范围
                    ↓
     对照规格、数量、价格、金额与条款
                    ↓
       识别关联影响、复算并生成候选
                    ↓
        差异反馈 → 用户补充更正依据
                    ↓
        联动更新相关成果，再次校验
                    ↓
           新版本报价 / PI 草稿
                    ↓
            文档审阅与原生导出
```

W2 复用 W1 的规格、设计、BOM 和报价，不重新猜测成本。数量变化但规格未变时，不必重复生图，也不应无理由取消样品的规格批准。

### 3.3 变更联动的位置

**变更联动是两个工作流共用的底层产品机制，不是需要用户单独打开的第三个流程。**

用户可以从聊天、文件编辑或新增资料发起变化。系统负责发现影响、继续执行；只把缺少事实、存在冲突或需要批准的部分交给用户。

## 4. 竞品数据分析

### 4.1 输入

使用少量公开资料快照或用户提供的竞品资料，默认约三条。每条记录来源、采集时间、产品类别、可见特征及可用的尺寸、材料、价格、图片等信息。

实际没有的字段保持未知。合成资料逐条标记，不伪装成真实市场调查。

### 4.2 输出

| 内容 | 要求 |
| --- | --- |
| 竞品比较 | 对比使用场景、结构、收纳、配色、标识、包装和可见风格 |
| 有依据的观察 | 能定位到具体资料，不编造销量、评价和认证 |
| 候选设计建议 | 解释与客户需求的关系，不自动覆盖客户要求 |
| 待验证项 | 制造难度、材料性能、成本和市场效果没有依据时明确说明 |

零售价格与出口批发报价不直接排名。少量资料不用于宣称全市场份额或销售趋势。

### 4.3 与后续成果的关系

被采用的建议进入设计简报，保留来源和采纳记录。未采用的建议不进入规格、BOM 或报价。

新竞品资料改变原分析结论时，系统提示影响并更新分析草稿，但不能擅自改变已选方案。用户采纳新建议后，才继续传播到设计和相关业务成果。

## 5. 美工与 AI 产品模拟图

### 5.1 核心能力

| 功能 | 产品要求 |
| --- | --- |
| 设计简报 | 区分客户必需项、采纳的竞品建议、禁止擅改项和待确认内容 |
| 真实图像生成 | 调用图像引擎，保存输入版本、生成结果或失败，不用静态图冒充新生成 |
| 产品概念模拟图 | 表达明确的配色、外观、结构和 LOGO 位置 |
| 反馈修改 | 支持按用户文字调整设计并生成新图，保留旧图 |
| 客户方案编排 | 将图片、说明、规格和限制编排成可编辑文档 |
| LOGO 处理 | 使用用户提供的资源或明确占位，避免依赖模型精准生成文字 |
| 图与规格检查 | 检查明显的颜色、结构和位置差异；不确定项可由用户标注 |

### 5.2 图像身份

产品图明确标记：

**“AI 产品概念模拟图 · 用于外观沟通 · 非实物摄影、工程图或确认样”。**

尺寸来自客户或产品资料，可在图外标注，不能由像素推算精确尺寸。客户认可外观方案、批准实际样品、接受商业条款，分别记录。

### 5.3 与变更联动的关系

改变可见的颜色、结构或标识位置时，系统识别需更新的图像，并更新引用该图的提案、规格或打样文档。

只改变背景或版式，不自动改变 BOM 成本和实际样品批准。只改变订单数量，不重新生成不受影响的产品图。

新图生成中或失败时，旧图可以作为历史查看，但不得继续被标为“已匹配当前设计”。新图完成并通过相应检查后，关联文档更新为新图版本。

本版不包含完整 CAD、三维建模、多角度工程一致性或完整精修软件。

## 6. 简易 BOM 识别、成本核算与报价

### 6.1 输入

支持清晰的 PNG/JPEG 简易表格图片，以及简单 XLSX 工作表。原文件保留，识别结果与原表可对照。

演示使用的自制资料统一标记为“合成测试 BOM / 模拟商家成本表”。系统必须处理实际上传内容，不能按文件名返回预置总价。

不承诺手写、严重模糊、多页复杂清单、宏或任意 Excel 功能兼容。

### 6.2 识别内容

行项目至少包括材料或费用名称、规格、每包用量、单位、单价、币种、原表合计及来源位置。表级信息包括适用产品与规格、数量范围、费用范围、未知费用和来源版本。

净用量与含损耗用量需要区分。工费、包装、检验和运杂分摊不能被重复计入，也不能假定纯物料 BOM 已经覆盖全部报价成本。

### 6.3 核对与计算

实际提取行项目后，检查小数点、数量、单位、单价和源表合计；用户可核对或修正。关键值不清晰时，暂停对应核价，不影响其他能够继续的工作。

```text
行成本 = 已核对的每包计费用量 × 对应单位价格
单位总成本 = 材料行成本 + 工费 + 其他明确计入的费用
建议报价单价 = 单位总成本 / (1 - 目标毛利率)
货款合计 = 订单数量 × 最终报价单价
定金 / 尾款 = 按已有商务条件计算
```

使用确定性计算和明确的精度、舍入规则；金额不能由模型自由生成。缺少付款比例时不自动填写，未知费用不等于零。

### 6.4 与变更联动的关系

BOM 用量、单价或费用变化后，自动重算成本和建议报价，更新相关工作稿，并检查客户报价、打样费用及 PI 是否受影响。

用户直接调整客户售价，不等于修改供应商成本。存在人工锁定售价或已接受价格时，系统保留其历史和适用范围，展示新成本及影响，不偷偷改写既有商业承诺。

设计超出 BOM 适用范围时，自动将相关报价标记为需重新核价；不能沿用旧价声称新方案已经核定。

确认“识别正确”只证明转录经过核对，不代表供应商价格已经得到外部验证。

## 7. 通用文件编辑器

### 7.1 编辑能力

| 类型 | 必须支持 | 兼容边界 |
| --- | --- | --- |
| 文档 | 正文、标题、表格、图片插入与替换、基础排版、保存 | 声明支持的 DOCX 范围，不承诺任意复杂排版无损 |
| 表格 | 单元格编辑、行列增删、复制粘贴、格式、基础公式、保存 | 简单 XLSX，不运行宏、外部链接或不支持的函数 |
| 图片 | 预览、选择、替换、插入文档和下载 | 设计修改主要通过生图反馈，不建设完整绘图软件 |

编辑器是实际工作环境，不能以固定字段卡片或表格截图替代。

### 7.2 编辑就是变更入口

用户在文档或表格中改动已保存后，系统自动识别业务字段变化，进入联动处理；不要求用户再向 Agent 重复描述，也不要求逐份点击“同步”。

```text
直接编辑 → 保存工作稿 → 识别变化
→ 查找关联成果 → 自动修改或标记待确认
→ 重算与校验 → 展示更新结果
```

普通输入可在保存稳定后触发，不以每次按键重生成所有文件。

### 7.3 自由编辑的边界

文件内容与计算依据必须保持对应。删除关键字段、破坏表格映射或使用不支持公式时，保留用户编辑，但标记需要复核，不能沿用旧校验结果。

Agent 不无声覆盖人工备注和锁定内容；发生冲突时说明冲突位置。原始外部文件只读保留，修改写入工作副本。

## 8. 原生 Office 多格式导出

### 8.1 格式与成果

| 成果 | 导出格式 | 主要受众 |
| --- | --- | --- |
| BOM / 成本表 | XLSX，保留可编辑输入及支持的公式 | 内部 |
| 设计提案、规格、打样资料 | DOCX；客户提案同时支持 PDF | 客户或供应商 |
| 客户报价 | XLSX + PDF | 客户 |
| PI 草稿 | DOCX + PDF | 客户 |
| 产品模拟图 | PNG/JPEG，附用途和版本说明 | 外观沟通 |

XLSX、DOCX 必须是真实原生文件，不以 HTML 改后缀或截图冒充。PDF 与对应可编辑成果来自同一内容版本。

### 8.2 导出也进入联动范围

上游内容改变后，已生成的相关 PDF、DOCX、XLSX 标记为旧版本；系统自动排队更新当前工作稿的导出成果，不等待用户发现文件落后。

新文件尚未生成、校验未通过或仍需批准时，“下载当前版本”必须显示对应状态，不能悄悄返回旧缓存。旧文件可从明确的历史入口查看。

内容修改、原生格式生成和可对外交付是三个不同状态。自动生成新版文件不代表已经对外发送或获得客户接受。

### 8.3 受众和内容边界

客户报价从允许披露的字段生成干净文件，不只是隐藏内部成本列。客户文件不能带内部成本、毛利、隐藏工作表、秘密公式引用、内部批注或未经允许的附件。

内部未核验草稿可以保存；存在硬错误时，不得以“客户可交付版本”导出。PI 保留草稿及待确认标识。

某个格式生成失败时，明确报告该格式失败，不用其他格式静默替代。

## 9. 工作流的输入、输出与完成条件

| 项目 | W1：设计与报价 | W2：反馈与订单确认 |
| --- | --- | --- |
| 主要输入 | 客户询盘、产品与竞品资料、BOM、商务规则、可选 LOGO | W1 成果、外部样品记录、客户反馈、PO及更正依据 |
| Agent 工作 | 分析、设计、生图、识别 BOM、计算、生成与校验 | 识别确认与变更、核对 PO、联动修订、计算与生成 PI |
| 用户参与 | 补充未知、核对重要识别值、选择设计、审阅成果 | 补充实际确认依据、处理冲突、审阅商务文件 |
| 主要输出 | 设计提案、规格、BOM/成本、报价、打样资料 | 差异报告、必要的修订成果、PI 草稿、待确认条件 |
| 完成条件 | 本次目标要求的成果已形成，相关内容一致，支持编辑与指定格式导出 | 本次订单差异已处理，PI与其依据一致，残余前提明确 |

部分成果可先返回，不能将“部分完成”标成全部成功。生图失败不抹掉已经完成的 BOM；成本缺失不阻止继续制作概念提案。

两条工作流中的任何反馈，都在原业务上下文继续，保留已经正确完成且未受影响的成果。

## 10. 核心机制：变更意图驱动的全链路联动

### 10.1 产品定义

**一旦识别明确的变更意图，Agent 自动查找当前业务中所有需要跟随修改的已纳管文件和数据，推进更新、复算、检查与导出版本刷新。**

这不是仅弹出“有文件需要更新”的提醒。对依据充分、可逆的工作稿修改，系统默认直接执行并留痕；需要补资料或批准的部分，才交给用户。

用户不需要逐份指出“还要改报价单、打样资料和 PI”。

### 10.2 触发来源

| 来源 | 典型变化 | 处理 |
| --- | --- | --- |
| 客户反馈进入工作台 | 改数量、颜色、LOGO、包装或交期要求 | 识别请求和影响，形成关联候选；不自动等同于双方已批准 |
| 用户主动指令 | “换成彩盒，并更新所有相关资料” | 直接识别变更范围，自动推进允许的修改 |
| 用户编辑文件 | 改 BOM 用量、单价、规格字段或报价条件 | 从已保存改动识别变化，走同一联动链 |
| 上传新资料 | 新 BOM、报价依据、更正 PO、样品意见 | 与当前使用依据比较，确认其适用关系后联动 |
| 设计方案调整 | 改结构、颜色、标识位置或选定新图 | 检查规格、图像引用、BOM及报价适用性 |

假设、询问、否定和正式修改必须区分。“如果改成彩盒会怎样”可以自动生成比较方案，但不能替换当前选择。

意图不清晰时先追问；明确的变化不反复询问“是否开始查找关联文件”。

### 10.3 覆盖范围

联动范围是**当前业务内已上传、已生成、已关联，且处于系统支持范围内的资料、工作文件、模拟图和导出件**，包括直接引用和间接依赖。

Agent 结合业务字段、已知引用和文档内容，检查可能遗漏的文字、表格、图像引用及多格式副本。即使用户没有逐个打开这些文件，也要纳入影响判断。

不能确认某个文件的内容或关联时，标为“影响范围待复核”，而不是直接宣布全链路已同步。

本版不自动监控尚未接入的邮箱、聊天软件或用户本地磁盘。资料进入工作台才触发处理；已经下载到外部的文件不会被后台改写。

### 10.4 自动处理闭环

```text
识别变更意图或已保存的字段变化
                  ↓
记录原值、新值、来源、变更范围
                  ↓
立即标记相关成果“需更新 / 影响待确认”
                  ↓
查找直接和间接受影响的文件、图像与导出件
                  ↓
区分：可自动更新 / 缺依据 / 需批准 / 实际不受影响
                  ↓
自动修改工作稿、重算、必要时重生图及刷新引用
                  ↓
校验关联内容，生成相应新版本和导出件
                  ↓
展示更新摘要、差异及仍需用户处理的事项
```

缺少成本、无法确定字段或遇到文件冲突时，暂停对应分支，而不是停止所有工作。用户补充后自动继续该变更，不需要从头运行整个业务。

### 10.5 不同变更的联动规则

| 变更 | 自动识别的主要影响 | 可以自动推进 | 不能擅自做的事 |
| --- | --- | --- | --- |
| 订单数量变化 | 报价、打样文件中的订单数量引用、PO/PI、付款计算和对应导出件 | 检查价格适用区间，更新内部工作稿并复算 | 不默认改变样品数量，不改写客户原 PO，不无依据继承新商业接受 |
| 材料、结构或工艺变化 | 规格、设计简报、模拟图适用性、BOM、成本、报价、打样及 PI | 更新规格候选，标记旧图/旧成本适用性，生成可确定的修改 | 不凭图推算新用量，不编造新价格，不将旧样品批准套到新规格 |
| BOM 用量或单价变化 | 成本、建议报价、相关客户文件与导出件 | 复算并修订未锁定工作稿，展示利润及价格影响 | 不覆盖已接受售价或人工锁定值，不伪造客户同意涨价 |
| 包装变化 | 包装规格、相关模拟图、BOM、报价、打样及 PI | 更新已知包装要求和已有新价格所支持的计算 | 没有新报价或工期依据时，成本、时间仍待确认 |
| LOGO位置或颜色变化 | 简报、图、规格、提案、打样及成本适用性 | 修订文字，按需生成新图，刷新引用 | 不假定所有视觉变化都不影响工艺或价格 |
| 仅改背景、排版或措辞 | 对应图像、文档和导出件 | 更新展示内容并检查是否改变语义承诺 | 不无理由重算 BOM、不取消未变规格的样品批准 |
| 更正 PO 中的金额错误 | 差异报告、PI、相关金额引用 | 保留更正来源，重新计算并检查 | 不改写原 PO，不把内部计算当客户已经更正 |

“全链路”指覆盖所有真正相关的成果，不是每次变更都重做全部文件。判断不受影响的文件可以保持原版本。

### 10.6 自动同步与审批分开

**工作稿同步默认自动，商业批准不自动产生。**

客户提出新要求后，可以立即生成新规格、设计和报价候选；原来的有效执行依据仍保留，直到相应确认满足。

已经批准、发布或交付的内容不可原地覆盖。系统生成新候选，指出替代关系及需要重新确认的范围；历史批准只属于它原来绑定的内容。

用户直接改客户售价时，按“售价调整”处理，不能反向篡改 BOM 或供应商价格来让表格看起来一致。存在人工修改冲突时，展示冲突并保护原编辑。

### 10.7 实时跟进与同步状态

变更被识别后，相关旧校验和旧导出资格立即失效或进入复核，不能等所有生成任务完成后才提示用户。

| 同步状态 | 用户应理解的含义 |
| --- | --- |
| 更新中 | 已发现影响，正在修改、计算、生成或导出 |
| 待补充 / 待复核 | 已定位关联，但缺少依据、存在冲突或无法确定内容 |
| 已同步 | 已与本次工作版本一致；不代表客户已经批准 |
| 更新失败 | 部分步骤失败，保留结果并说明重试入口 |
| 历史 / 已被替代 | 仅供追溯，不作为当前工作成果使用 |

批准状态单独显示。文件可以“已同步、待客户确认”，不能把两种状态混成一个绿勾。

用户能查看本次变化、受影响文件、已更新内容、未完成原因和下一步。默认不要求逐文件确认无歧义修改，但允许查看差异、纠正关联范围和撤销工作稿修改。

### 10.8 连续变化和失败处理

运行期间收到更新要求，以新需求重新判断相关输出。旧输入生成的迟到图片、计算结果或文件不得覆盖当前版本。

Agent 自己传播的修改属于同一次变更，不应再次触发无限循环。无关人工编辑应尽量保留；无法安全合并时明确提示。

部分文件失败时，其他正确成果可以保留，但受影响的交付包不能显示“全部已同步”。修复后只继续必要步骤。

已经下载或交付到外部的文件只能记录需要换发，不能宣称外部旧文件已自动更新。

## 11. 来源、工作稿和版本关系

| 对象 | 产品含义 |
| --- | --- |
| 原始来源 | 客户原文、PO、BOM、竞品资料等原始内容，保留出处和原始版本 |
| 当前工作稿 | 用户和 Agent 正在编辑的内容，允许不完整或尚待校验 |
| 一致业务版本 | 本次相关文件、计算依据、图片引用和检查结果相互一致的快照 |
| 批准依据 | 哪个主体批准了哪个规格、样品或商业条件，不由新文件生成自动继承 |
| 导出件 | 对应确定内容版本和受众的实际文件，有独立生成与同步状态 |

同一次跨文件修改，相关业务内容校验一致后才更新当前版本；不能把新数量、旧报价和更旧 PDF 混成一个成功结果。与变更无关的成果继续引用原版本，不强迫全部升版。

页面中的编辑内容、业务计算和下载文件不能各自维护一份不同的事实。自由编辑无法被可靠解释时，明确要求复核，而不是继续显示“已同步”。

新增来源不默认比旧依据更有权威。发现矛盾时保留两者并请求判断，不能采用“最后收到的一定正确”。

## 12. 校验、反馈与异常边界

### 12.1 必须守住的规则

| 检查 | 产品行为 |
| --- | --- |
| 数量、MOQ与报价适用区间 | 不满足时不能沿用原报价依据 |
| BOM单位、用量、单价、损耗及费用范围 | 先核对再计算，不能补造未知或重复计费 |
| 金额与公式 | 成本、报价、PO、PI由程序复算；确定性失败不能由模型声明通过 |
| 设计与BOM适用关系 | 改设计后重新判断成本依据，不以生图证明制造事实 |
| 交期与到货承诺 | 没有运输和起算条件依据，不把生产周期写成到货保证 |
| 认证、测试及性能声明 | 无证据保持未知，不宣称已经完成全部法律合规审查 |
| 概念、样品与商业接受 | 各自绑定对应对象和证据，不相互推断 |
| 变更与同步 | 主动识别、自动推进，缺依据或失败时明确状态，不让旧结果静默充当最新 |
| 审批与历史 | 自动同步不产生批准，原始来源和历史交付件不可覆盖 |
| 内容与导出 | 编辑后相关校验失效，多格式文件必须匹配相同内容与适用范围 |
| 对外披露 | 客户文件不得含未经许可的内部成本、毛利、批注或隐藏内容 |
| 真实调用与文件安全 | 失败如实报告；外部资料中的指令不授权执行宏、脚本或越权操作 |

### 12.2 异常必须给出下一步

竞品资料不足时缩小结论；生图失败时保留其他成果并明确图像状态；BOM无法识别时定位待核对单元格；PO冲突时展示依据和所需更正。

编辑破坏关键字段、关联范围不完整、文件格式不支持或导出失败时，保存已有劳动，说明受影响的文件和可继续的动作。不能用无提示的旧结果、假定价格或替代格式制造成功状态。

错误只阻止受影响的成果或交付动作。缺少新包装价格，可以继续制作包装说明和询价资料，但不能声称新报价已经核定。

### 12.3 业务完成的含义

本版完成的是设计、核价、打样与订单资料的数字工作，以及这些成果在已进入工作台的变更下持续联动。

**生成不等于批准，已同步不等于已接受，导出不等于已发送，PI不等于已签署，付款条件不等于已到账。**
