## 1. 产品定义

**让每个外贸人都能调用企业知识、素材和专业能力，在一个工作台里完成从客户需求到报价、内容、检查和跟进的完整业务。**

用户围绕业务目标工作，例如：“处理这条询盘，找合适的商品，算报价，配产品资料，检查风险，再生成客户回复。”系统在同一个案例中组织运营、业务、采购、美工和合规相关能力。

岗位是专业能力分类，不是用户身份限制。产品不要求用户切换五种身份、创建五个账号，或把每一步强制转交给另一位人员。需要外部事实时，向当前用户指出缺少的资料；已有依据的步骤继续执行。

知识 Wiki、资产库、能力市场、对话和画板共同服务这一目标。开发团队的前端、后端、业务模块分工，与最终用户能够完成哪些岗位工作无关。

## 3. 目标用户与使用场景

### 3.1 目标用户

- 需要独立完成多项工作的中小外贸商家、业务经营者。
- 需要调用其他专业知识与工具的运营、业务或采购人员。
- 已有商品和客户资料，但资料分散、重复操作多的电商团队成员。

用户不必了解 Skill、CLI、MCP 的技术含义。前台按业务动作展示能力；能力详情中再解释执行方式、数据来源和依赖。

### 3.2 核心使用场景

用户收到一条询盘后，在一个工作空间完成需求理解、商品匹配、双语回复、报价计算、素材准备、规则检查与后续修改。处理过程引用同一套商品事实和资料版本，避免在不同页面重复输入。

首版以阿里国际站 RFQ 业务语境为背景，演示美国英语和墨西哥西语表达，内部核对事项使用中文。首版覆盖“询盘理解与首次回应”“客户异议与报价方案更新”两个相关场景。

## 4. 问题、价值与衡量方式

| 业务问题 | 产品作用 | 可记录的指标 | 本次不能据此宣称 |
|---|---|---|---|
| 询盘转化低 | 理解需求、识别缺口、提供有依据的方案和下一步 | 首次形成可审核方案的耗时、关键问题遗漏数、客户反馈阶段 | 实际转化率已经提升 |
| 重复人力成本高 | 复用 Wiki、素材、技能和工具执行步骤 | 已复用资料数量、重复录入次数、生成后人工修改项 | 未经测量的节约比例 |
| 跨岗位协同难 | 同一用户使用多种专业能力，产物共享上下文 | 一次修改需要手工更新的产物数、跨产物冲突数、待确认项 | 已实现实时多人协同或全岗位专业替代 |

目标不是增加对话字数或能力卡片数量，而是减少用户推进同一件业务所需的重复工作。真实成交、样品确认和下单指标需后续真实业务数据验证。

## 5. 产品原则

1. **以业务案例组织工作。** 用户在一个案例中持续处理需求与反馈，而非每个工具重新开始。
2. **专业能力按需调用。** 一个用户可使用全部已启用能力，不设置岗位墙。
3. **事实和建议分开。** 客户要求、商家事实、AI 建议、未知项分别存储和展示。
4. **结果可引用、可修改、可追溯。** 文字、报价、素材与风险都关联来源和版本。
5. **确定性计算独立于生成。** 数量、价格、MOQ、金额和版本检查由程序完成。
6. **未知保持未知。** 运费、税费、到货、认证证据缺失时不得填零或编造。
7. **原型如实展示边界。** 本地计算、预置素材与模拟调用采用不同标签。

## 7. 信息架构与页面布局

一级导航：**工作台 / 知识 Wiki / 资产库 / 能力市场 / 版本记录**。

工作台采用三部分：左侧资源导航，中间持续对话与当前上下文，右侧业务画板。顶部采用桌面客户端式业务标签，标识当前案例，并保留版本、演示状态和导出入口。标签只表达当前业务上下文，不代表已经支持多项目或多标签会话。内容详情通过抽屉展示，保留用户的工作现场。

画板的六类卡片为：客户需求、供货事实、报价草案、产品资料、风险与待确认、双语回复。下一步和供货核对通过相关详情展示。卡片表示内容与能力结果，不表示需要另一个岗位的人接单。

### 7.1 视觉规范（0.2）

设计参考为用户指定的 [工作台站点](http://118.178.229.75:40002/)。本次依据是该站公开 `src/index.css` 的样式信息：白灰黑主色、轻分隔、圆角、浅色半透明侧栏与轻阴影。HTTP 请求返回 200 且公开 CSS 已读取；浏览器截图多次超时，尚未验证该站最终渲染效果。以下为采纳的视觉方向，不是逐像素复刻承诺。

| 视觉项 | 规范 | 用途 |
|---|---|---|
| 主操作色 | `#000000` | 主要动作、当前状态的重点表达 |
| 主文字色 | `#1a1c1e` | 标题、正文、关键业务值 |
| 内嵌区域底色 | `#f4f4f5` | 次级背景、输入或分组区域 |
| 画布底色 | `#fcfdfe` | 业务画板和大面积内容空间 |
| 细边框 | `rgba(31, 34, 37, 0.08)` 至 `rgba(31, 34, 37, 0.10)` | 面板、卡片、分栏和轻分隔 |
| 基础圆角 | `10px` | 按钮、输入框和面板的统一尺度；胶囊与图标等可按用途调整 |
| 侧栏 | 浅色半透明、轻阴影 | 清楚区分导航层与业务内容，避免厚重装饰 |
| 顶部 | 客户端式当前业务标签 | 保持案例身份可见，与下方对话及画板共享上下文 |

视觉层次以留白、字重、边框和轻阴影组织。中间对话承接输入与过程，右侧画板承载结构化结果；减少大面积装饰色，风险仍保留可辨认的提示色、图标和文字，不因黑白基调而失去语义。

五个导航入口、画板选中与拖动状态、能力启停状态、风险批注、版本对比和导出按钮应保持易辨认、可操作。详情抽屉沿用同一视觉体系。桌面优先，同时维持窄屏对话、资料和导出入口可达。

本轮只采纳设计参数和组织思路，独立调整现有原型的实现，不复制参考站源代码。视觉验收应检查分栏宽度、文字对比、焦点、遮挡、滚动、画板操作以及原有业务回归；不能仅凭参考站 CSS 或原型源码认定截图与交互已经验收。具体变更记录见 [设计更新说明](DESIGN_UPDATE.md)。

## 8. 功能需求

### 8.1 工作台与对话

| 编号 | 要求 | 验收条件 |
|---|---|---|
| FR-01 | 显示当前案例、版本、资料/生成模式 | 用户能区分演示样例、当前版本与历史版本 |
| FR-02 | 接受中文需求或客户原文，提供固定演示输入快捷入口 | 快捷入口与提交文字进入同一个处理路径 |
| FR-03 | 支持初始输入后的至少两次修改 | 数量、方案、接受状态正确继承和更新 |
| FR-04 | 显示本次使用的能力、来源和产物 | 模拟调用明确标识，不展示伪造思考过程 |
| FR-05 | 显示已选画板卡片作为上下文，可移除选择 | 提交时采用所选内容及当前案例版本，不静默引用旧版本 |
| FR-06 | 对原型支持范围外的输入给出可执行建议 | 不生成“任意需求均已完成”的成功状态；引导至支持的演示动作 |

初始演示可以预载 V1 案例，便于用户立即看到界面；预载内容必须标为样例。通过“重新体验”可回到 V0，再点击“分析这条询盘”生成 V1。任何预载状态不计作本次真实模型执行。

### 8.2 无限画板工作空间

| 编号 | 要求 | 验收条件 |
|---|---|---|
| FR-07 | 显示统一案例的需求、商品、报价、素材、检查与回复卡片 | 不将各卡片做成互不相干的独立数据副本 |
| FR-08 | 支持选择和取消选择卡片，再将所选内容带入对话 | 已带入的上下文有单独提示和清除按钮；清除后下一轮不记录这些卡片引用 |
| FR-09 | 支持拖动卡片、画布缩放、恢复合适视图 | 不改变业务数据；卡片内容在缩放后仍可查看 |
| FR-10 | 点击内容打开详情抽屉 | 抽屉显示完整内容、语言、来源、版本和风险 |
| FR-11 | 需求变化后同步相关卡片 | 不出现 V3 需求与 V2 当前报价混用；历史内容单独标识 |

卡片移动只改变布局；修改需求才创建业务版本。点击卡片选择，Shift＋点击多选；通过“用选中内容继续”把引用带入对话，使用输入区上下文标签的关闭按钮清除已带入内容。当前 Demo 将节点 ID、来源与基础版本记录到本轮快照和执行记录。首版自动生成必要关联，后续再开放用户编辑连线。画板支持真实拖动、缩放、选择及本地保存，但不宣称实现完整无限画板编辑引擎。画板操作不能绕过资料或业务校验。

### 8.3 知识 Wiki

| 编号 | 要求 | 验收条件 |
|---|---|---|
| FR-12 | 按商品知识、商务规则、表达规范等组织条目 | 至少能找到本次演示使用的商品事实与规则 |
| FR-13 | 支持检索、查看详情和引用到当前工作 | 引用有条目 ID、版本、来源和适用范围 |
| FR-14 | 区分官方说明、商家政策、演示设定 | 不把演示报价有效期包装成平台统一规定 |

正式 MVP 中，导入内容先进入待审核状态；用户确认后形成新知识版本。模型生成文本不能未经确认自动成为可信商品事实。当前 Demo 使用只读种子条目，不提供编辑、上传或向量检索；“关联到当前业务”会把知识来源加入后续执行的引用记录。

### 8.4 资产库

| 编号 | 要求 | 验收条件 |
|---|---|---|
| FR-15 | 展示产品素材、规格资料和已生成业务产物 | 能区分预置资产与本次生成草稿 |
| FR-16 | 查看资产详情并引用到画板/当前上下文 | 引用正确 SKU、语言、来源和版本 |
| FR-17 | 保存本次业务产物并保留草稿状态 | 保存不等于审核通过或已发送客户 |

演示素材采用本地 SVG 示意图，并标明“演示素材”。没有认证材料时显示缺失，不提供假证书。Demo 检查素材 SKU 是否匹配当前方案，并保留材料草稿的业务版本。目标 MVP 在资产更新后，还应提示依赖旧版本的产物过期；当前 Demo 没有素材编辑、更新与完整过期依赖机制，不能宣称已完成这部分。

### 8.5 能力市场

| 编号 | 要求 | 验收条件 |
|---|---|---|
| FR-18 | 以业务名称展示 Skill、CLI、MCP 能力 | 用户不理解协议也能知道能力用途 |
| FR-19 | 展示能力说明、输入输出、依赖、版本和状态 | 模拟连接不能显示为已连接真实平台 |
| FR-20 | 能启用/停用能力，后续执行遵守启用状态 | 停用后不能继续伪装调用该能力 |
| FR-21 | 记录能力执行与对应产物 | 记录包含模拟/真实模式、输入引用、结果和失败原因 |

工作流声明必需和可选能力。必需能力被停用时，在运行前阻断，提示启用方式，不提交新业务版本。当前 Demo 的“准备客户资料”是独立步骤：停用时仍可完成报价，但“加入画板”和整理材料会提示需先启用；不会伪装成已完成素材准备。启停不删除既有产物和历史。目标 MVP 如将可选步骤纳入一次工作流，应在结束时明确报告被跳过的步骤。

目标 MVP 的 Skill 组织业务步骤；CLI 调用受控程序；MCP 通过真实协议查询可用数据或工具。当前 Demo 使用本地逻辑模拟这些交互，展示调用方式不等于协议已接入。

### 8.6 校验、历史与导出

| 编号 | 要求 | 验收条件 |
|---|---|---|
| FR-22 | 对产物执行独立业务检查 | 至少覆盖信息真实性与报价/合同条款两类 |
| FR-23 | 用文字批注和风险标记反馈 | 风险可定位到具体内容或字段，并有原因和建议 |
| FR-24 | 保存版本并支持查看差异 | V1/V2/V3 可回读，旧版本不被新版本覆盖 |
| FR-25 | 导出当前选定版本的 HTML 报告 | 内容、金额、风险与所选版本一致，保留演示标识 |
| FR-26 | 支持“重新体验”和刷新恢复 | 重新体验的影响范围清楚；刷新后恢复本地保存状态 |

导出内容必须转义用户输入和生成文本，不执行模型或用户提供的脚本。草稿生成、保存、导出、发送和成交是不同事件；Demo 不自动标记已发送或已成交。

## 9. 两个工作流与三个版本

### 9.1 演示事实

下表全部为合成演示设定，不是真实库存或商业报价。

| 商品 | 起订量/可用量 | 价格 | 交期事实 |
|---|---|---|---|
| BAG-CUSTOM 定制帆布袋 | MOQ 500；库存未提供 | 500–999 件 USD 2.40；1000 件起 USD 2.00 | 稿件和付款确认后生产 14 天 |
| BAG-STOCK 现货无印花款 | MOQ 100；演示库存 800 | USD 1.80/件 | 付款确认后 3 天内出库 |

两款均未提供认证证据。运费、税费、运输时间和最终总额未知。报价有效期 7 天是演示商家政策，与客户要求 7 天到货无关。

### 9.2 工作流一：询盘理解与首次回应

输入：“墨西哥客户要 1000 个定制帆布袋，希望 10 天内收到，并询问是否有认证。请分析并准备英文、西语回复。”

处理：提取需求 → 查商品与规则 → 发现生产 14 天与 10 天到货要求冲突 → 识别认证资料缺失 → 生成双语澄清回复、需求摘要和风险 → 保存 V1。

当前 Demo 的 V1 只完成需求与供货分析，尚未形成报价。画板报价区明确提示继续准备方案，不显示 USD 2,000.00 为已确认报价，更不能承诺 10 天到货。

### 9.3 工作流二：异议处理与报价方案更新

第一次修改：“客户改成 300 件试单，希望 7 天内要用。给我备选方案和报价。”

处理：保留原定制要求 → 发现 300 件不满足定制 MOQ 500 → 从已提供的候选商品资料中提出现货无印花款（本 Demo 为合成数据）→ 标记为待客户接受 → 程序计算商品小计 USD 540.00 → 生成双语回复、报价草案、供货核对项与风险 → 保存 V2。

V2 的现货方案是 `proposed`。不能为了让报价通过而把客户的定制要求悄悄改成无印花，也不能宣称已满足 7 天到货。

第二次修改：“客户接受现货无印花方案。运费待确认，写清 3 天是出库时间，不保证 7 天到货。”

处理：接受状态更新为 `accepted` → 保持商品小计 USD 540.00 → 更新所有相关回复和核对项 → 明确出库与到货区别 → 保存 V3。

V3 的运费、税费、运输时间和总额仍为未知；客户接受商品备选不等于订单已经成交。

## 10. 业务不变量与规则反馈

| 编号 | 不变量 | 处理方式 |
|---|---|---|
| BR-01 | 价格来自有效价表，不由文案生成 | 使用整数分或十进制计算，格式化为两位小数字符串 |
| BR-02 | 数量 × 单价等于商品小计 | 不一致时阻止发布错误金额 |
| BR-03 | 未知运费/税费不等于零 | 保存为 null，界面显示待确认；最终总额保持未知 |
| BR-04 | 出库不等于到货 | 缺运输依据时不得生成确定到货承诺 |
| BR-05 | 认证声明需要证据 | 无证据显示待确认；生成肯定认证声明时提示并修正 |
| BR-06 | 备选不等于接受 | 只有客户明确接受当前具体方案才改变状态 |
| BR-07 | 同一版本所有产物使用同一需求 | 数量、SKU、金额、交期口径同步更新 |
| BR-08 | 来源必须可定位 | 引用指向实际资料/规则 ID 和版本 |
| BR-09 | 一人可推进多个专业能力节点 | 不因岗位标签限制当前用户操作 |

信息真实性检查包含商品规格、认证和交期声明；报价/合同检查包含金额、费用范围、付款/有效期与条款缺失。产品只说明检查覆盖的规则，不显示笼统的“全球合规”。

风险严重度建议：阻断错误结果的 error；可以随草案保留的 warning；说明类 info。缺少运费和需确认方案属于 warning；错误金额、无依据的肯定认证或到货保证需要修复。两种语言的数字和承诺应一致。

## 11. 状态与数据模型

### 11.1 状态

- 业务版本：初始资料 → V1 需求分析 → V2 备选草案 → V3 接受方案。
- 执行：待执行 → 执行中 → 成功/失败；失败保留上一个成功版本。
- 产物：草稿、待确认、当前、历史/过期。未知项仍存在时不应显示全部通过。
- 能力：启用、停用；连接另分模拟、已连接、不可用，避免混用。
- 客户推进：询盘已录入、方案待确认、客户反馈已记录等；真实发送与订单状态需外部证据。

### 11.2 核心对象

| 对象 | 关键字段与关系 |
|---|---|
| Case | id、title、market、languages、currentRevision、资料模式、创建/更新时间 |
| RequirementRevision | caseId、revision、客户原文、quantity、requestedSku、selectedSku、customization、到货要求、optionStatus、变化项 |
| Product | sku、名称、规格、MOQ、stock、priceTiers、币种、productionDays、dispatchDays、计时条件、source/version |
| WikiEntry | id、类别、正文、适用范围、sourceKind、sourceUrl、version、演示标识 |
| Asset | id、类型、SKU、语言、内容/本地位置、source、version、draft/approved 状态 |
| Capability | id、kind、业务名称、说明、enabled、输入输出、dependencies、version、执行模式 |
| Run | id、caseId、baseRevision、workflow、输入/上下文引用、状态、执行记录、能力版本、错误 |
| Artifact | id、caseId、revision、kind、language、正文/结构化报价、sourceRefs、关联风险、状态 |
| Risk | id、category、severity、ruleRef、目标字段/产物、原句、原因、建议 |
| CanvasNode / Edge | nodeId、内容引用、位置、选中状态；边关联内容依赖，不重复保存报价事实 |
| FollowupAction | caseId、业务动作、依据、状态、可选时间；默认由当前用户推进 |

`owner_role` 等旧版字段若继续保留，只作为专业能力标签，不是账户 ID 或强制人员分派规则。完整平台升级时可改为 `capabilityLabel`，但应统一迁移契约，不能让三个开发包各自改名。

### 11.3 版本与同步

一次成功的业务修改原子更新需求、当前产物、风险与变化记录。画板引用新版本结果，历史快照保留。布局调整和能力启停不创建业务版本；它们分别保存为工作区状态和能力配置。

选中历史内容时，界面明确标记版本。当前 Demo 的旧版本只读，必须点击“回到最新版本继续”才可执行、关联资料或整理材料。目标 MVP 若支持使用历史资料进行新生成，应要求用户明确选择并提示版本差异；不得静默把历史价格当成当前价格。

## 12. 目标后端与接口建议

以下是完整 MVP 的接口建议，**不是当前纯前端 Demo 实际调用的接口，也不表示旧 v1 三人任务包已实现这些能力**。

| 领域 | 建议接口职责 |
|---|---|
| 案例与版本 | 创建/读取案例、读取指定版本、提交修改并建立运行 |
| 运行 | 查询阶段、结果、错误和实际能力调用记录 |
| 知识 | 查询条目、详情、版本；导入/审核形成新版本 |
| 资产 | 列表/详情、引用、保存产物草稿、更新版本 |
| 能力 | 目录/详情、启停、依赖检查、连接状态、执行记录 |
| 画板 | 保存节点位置、视图、引用和依赖；内容事实仍来自案例/产物 |
| 导出 | 按指定成功版本生成安全的 HTML/PDF 或表格 |

已有 `/api/cases`、`/api/runs`、`/api/knowledge` 等 v1 思路可保留；新增市场、资产和画板对象需要统一定义结构与兼容策略。正式模型接入、CLI 受控执行和 MCP 协议适配须分别验收，不能由前端图标或调用动画代替。

## 13. 异常与降级

| 情况 | 用户反馈与数据行为 |
|---|---|
| 输入超出 Demo 支持范围 | 提示可体验的动作，不假装完成任意生成 |
| 必需能力停用 | 说明缺少哪项能力及恢复入口，不创建新版本 |
| 素材整理能力停用 | 报价流程仍可执行；加入素材或整理材料时提示启用对应能力 |
| 原型本地存储损坏/不兼容 | 当前 Demo 对 JSON 解析失败或顶层格式不兼容回退默认样例；更完整结构校验与恢复提示属于后续改进 |
| 浏览器禁止本地存储 | 本次会话继续可用，明确提示刷新可能不保留 |
| 商品或证据不足 | 返回具体缺口，不编造 SKU、认证或价格 |
| 数量低于 MOQ 或超过已知库存 | 给出不能执行的原因或有依据的备选，不输出有效承诺 |
| 目标 MVP 模型超时/输出非法 | 有限重试或修复；失败不覆盖成功版本 |
| 目标 MVP 外部连接失败 | 显示真实失败；可查看历史，不能以样例冒充成功 |
| 导出失败 | 提示重试或使用浏览器保存，不把失败写成已导出 |

## 14. 可访问性与交互质量

- 导航、提交、能力开关、抽屉关闭、缩放与重置均可用键盘操作。
- 表单有明确标签；风险不能只依赖颜色，要有文字或图标说明。
- Drawer/Dialog 支持 Escape 关闭，并保持合理焦点顺序。
- 拖拽不是唯一查看方式；卡片内容可直接点击或键盘打开详情。
- 提交过程中避免重复操作；完成/失败有明确反馈。
- 桌面宽屏优先；窄屏至少能访问对话、资料和报告，不因画板宽度导致核心按钮不可达。

## 16. 与比赛要求的对应

| 赛事要求 | 产品设计对应 | Demo/后续验证界限 |
|---|---|---|
| 两种语言或两类角色/场景 | 英语、西语客户回复；中文核对清单 | Demo 展示样例本地化，真实模型质量需后续验收 |
