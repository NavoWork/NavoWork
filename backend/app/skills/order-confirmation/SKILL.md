# PO、PI 与付款保障

## 何时使用
客户发来 PO，或需要制作 PI/合同、核对订单条款、登记双方确认和付款计划时。

## 输入
- 已批准的报价和规格版本
- 客户 PO 原件
- 卖方公司抬头、银行信息、HS 编码、收货人、单证要求
- 付款约定（定金比例、尾款、信用证等）

## 工具顺序
1. `get_case_context` 查看最新报价/规格、已有订单记录。
2. `read_source` 读取 PO；`search_knowledge` 查合同/PI 条款规则。
3. `record_order` 写入 PO、PI、卖方信息、单证清单、付款计划；工具自动生成与报价/规格的差异。
4. 有冲突时先向用户说明冲突字段；不要生成“已确认”的 PI。
5. 双方确认和付款核验只能由人工门禁记录；工具保持 pending。
6. 缺 PO 编号、金额、付款节点时用 `request_info`。

## 字段规则
- 差异至少核对：数量、单价、贸易术语、指定地点、付款方式、交期。
- PI 必须含买卖双方、产品/数量/单价/总额、贸易术语、付款方式、有效期/交货期。
- 买方和卖方确认必须使用不同证据，不能复用同一封邮件。
- 付款计划写比例/金额/到期日；核验只记录“待核验”，不写已到账。

## 完成标准
PO 差异清晰，PI 草稿完整，付款计划可执行；未人工确认前不得进入生产放行。
