# 打样与样品确认

## 何时使用
客户要求打样、样品寄出、收到样品反馈、客户批准或要求修改时。

## 输入
- 当前 `spec` 版本
- 客户打样要求、样品费/快递费约定
- 样品检查记录、照片、快递单号、客户反馈邮件

## 工具顺序
1. `get_case_context` 确认规格版本和已有样品轮次。
2. `read_source` 读取打样要求/客户反馈；必要时查知识库样品规则。
3. `record_sample` 记录种类（开发样/确认样/产前样）、轮次、编号、规格版本、费用、快递、单号、检查项、反馈、封样。
4. 客户批准只能由人工在门禁中记录；工具只把 approval 保持 pending。
5. 缺规格版本、样品编号或反馈时用 `request_info`。

## 字段规则
- 检查项：外观、尺寸、功能、做工、包装；每项 passed / failed / pending。
- 客户说“看起来不错，但改一下 logo”不等于批准；记录为修改要求，新轮次。
- 规格变更后，旧样品批准失效，必须提示重新确认。
- 样品费/快递费单列，不并入大货单价。

## 完成标准
样品轮次、检查、反馈和客户批准证据链完整；未批准时下游订单/生产保持阻断。
