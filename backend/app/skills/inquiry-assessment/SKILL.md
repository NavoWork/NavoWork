# 客户与询盘评估

## 何时使用
新询盘第一次进入工作台，或客户背景、询盘渠道、采购条件发生补充时。

## 输入
- 客户原始邮件/消息（case 原文或 evidence）
- 客户背景资料、官网、LinkedIn、历史往来（如有）
- 知识库中的客户评估规则（如有）

## 工具顺序
1. `get_case_context` 查看已有资料和阶段状态。
2. `read_source` 读取询盘原文；必要时 `search_knowledge` 查客户评估规则。
3. `update_customer_profile` 写入公司、国家、渠道、联系人、主营业务、背景核验项。
4. 用 `request_info` 只询问真正缺失且影响推进的信息：产品、数量、目标价、贸易术语、目的港、付款方式、认证、交期。

## 字段规则
- 客户没有明说的字段保持 null，不根据公司名或域名推断采购量、信用或付款能力。
- 背景核验项只记录“来源中能核对/待核验/需跟进”，不下信用结论。
- 询盘渠道：email / website / alibaba / amazon / linkedin / referral / unknown。
- 风险要具体，例如“客户要求 45 天到港，但船期未确认”，不要写泛泛的“存在风险”。

## 完成标准
客户背景、渠道、主要采购条件、待确认项和下一步清晰可读；下游需求节点仍为空。
