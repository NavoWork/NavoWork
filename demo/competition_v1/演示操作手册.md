# NavoWork 比赛演示操作手册

本包对应 PRD 的 Flow A、B、C：**询盘 → 需求/规格 → 询价核价 → 报价 → 变更维护 → 样品与订单确认 → 生产资料门禁 → 人工放行**。

全部客户、工厂、订单、邮件和付款记录均为模拟，统一演示日期为 2026-10-31。当前可执行终点是生产资料包放行；实际生产进度、出运、银行到账和售后尚未接入，不能在演示中说成已完成。

## 2. 同一项目跑通全部阶段：最快路线

以下 PowerShell 命令在仓库根目录逐条执行，浏览器刷新即可观察结果。需要 API 和 Worker 正在运行；尚未启动时另开终端执行 `backend/.venv/Scripts/python.exe dev.py`，已启动则复用。

脚本使用真实 API 和 LangGraph Worker 执行任务，再把本包明确提供的原件字段保存成可编辑成果新版本；它不代表模型已经自动识别所有字段。尤其是规格和报价条款，来自预先准备的模拟资料。`quote/change/order` 不登记六项业务批准。`change` 会代表本次演练操作者维护受影响节点并激活变更；需要现场逐项处理时改用第4节。

```powershell
# 1. 核价、补齐规格/报价条款，形成五类草稿；预期8.69美元
backend/.venv/Scripts/python.exe demo/advance.py --case de_a --step quote

# 2. 登记彩盒变更及A工厂新版，分析、修订、关联节点、激活、重新核价；预期9.21美元
backend/.venv/Scripts/python.exe demo/advance.py --case de_a --step change

# 3. 收到PO、样品及双方来件，生成/维护PI、生产指令、T&A和QC草稿；仍缺六项确认
backend/.venv/Scripts/python.exe demo/advance.py --case de_a --step order

# 4. 只查看缺口；可以停在这里，回界面手工逐项批准
backend/.venv/Scripts/python.exe demo/advance.py --case de_a --step check
```

此时进入 [01业务资料与审批](http://127.0.0.1:5173/workbench?case=inq_competition_de_a)，按第5节的六项表格操作。也可在核对本包材料后，显式执行以下两条演练命令：

```powershell
# 5. 明确登记模拟人工确认，六项门禁应变成ready_for_manual_release
backend/.venv/Scripts/python.exe demo/advance.py --case de_a --step approve

# 6. 再次检查门禁并放行模拟生产资料包
backend/.venv/Scripts/python.exe demo/advance.py --case de_a --step release
```

批准和放行各自需要单独执行，初次导入不会替你完成。脚本只接受本机服务中的指定模拟德国项目。若收到“有进行中/待回答任务”，先在画板完成或取消该任务；若有开放变更，先处理变更再核价。网络超时后先刷新检查状态，避免重复提交。

完成一个阶段后再进入下一阶段；对已经进入订单/批准阶段的项目，不要重新运行首次报价，否则会生成新版本并使原批准失效。重演应使用新批次。

## 3. Flow A：首次询盘到报价（界面操作）

进入01，阅读操作卡，右侧发送：

> 请分析3000件背包需求，列出缺失信息；参考核价规则，先不承诺45天到港。

在“引用知识与核价条件”选择产品规格、核价规则、贸易条款三篇 Wiki。知识版本作为通用参考；当前订单数量和包装要以客户原件为依据。

初始文件：`de-inquiry.eml`、`spec-DE-v1.txt`、`quote-a1.txt`、`quote-b1.txt`，画板还有产品示意图与供应商报价工作簿。供应商报价字段已人工预录，可直接选择“工厂 A｜宁波远行箱包（模拟）”。不需要再次创建同名报价。

核价条件填写：汇率 **7.2**、毛利率 **20**（百分数）、数量 **3000**。选择核价与报价节点或在对话中发送：

> 请依据工厂A原件核算3000件背包报价，FOB宁波，45天到港只是客户期望。

| 报价来源 | 基础成本CNY | 包装CNY | 内部国内费用CNY | 成本合计CNY | 报价USD/件 | 商品小计USD | 生产周期 |
|---|---:|---:|---:|---:|---:|---:|---|
| 工厂A原包装 | 44 | 2 | 4 | 50 | 8.69 | 26,070 | 28天 |
| 工厂B原包装 | 46 | 2 | 4 | 52 | 9.03 | 27,090 | 23天 |
| 工厂A彩盒 | 44 | 5 | 4 | 53 | 9.21 | 27,630 | 31天 |

公式为 `(基础+包装+国内费用) ÷ 汇率 ÷ (1−毛利率)`，单价向上保留2位，商品小计按该单价乘数量。生产周期从最终样品/图稿与付款条件具备后起算，不能等同于到港时间。FOB宁波、Incoterms2020；国际运费、保险、目的国税费没有计入本表商品小计。

预期产生规格、RFQ、供应商比较、成本、报价五类成果。点选成果可查看/编辑 JSON，“保存新草稿版本”会保留旧版。可用 `edits/spec-DE-v1.json` 补齐规格；报价还需填写：

```json
{
  "incoterm": "FOB",
  "namedPlace": "Ningbo",
  "incotermsVersion": "2020",
  "paymentTerms": "30% deposit, 70% before shipment",
  "validUntil": "2026-11-14",
  "sampleTime": "5 days",
  "productionTime": "28 days after final approval and payment conditions"
}
```

上述字段合并到现有报价内容，保留 `quote`、产品、数量和 `selectedSupplierOfferId`，不要把整个报价对象替换成这几个字段。点“校验”检查缺项，下载具体成果的PDF/XLSX/HTML草稿。右侧的双语回复是另一份可编辑草稿，未对外发送。

## 4. Flow B：彩盒变更与节点维护

比赛可直接进入02；沿01继续时，先从本包上传 `customer-packaging-change.eml`（客户变更）、`quote-a2.txt`（供应商报价）、`spec-DE-v2.txt`（客户需求）。资产库中的文件不自动等于当前Case收到的证据，需要在本Case“原始证据”登记。

在“通用变更与节点影响”选择客户变更邮件，输入：

> 包装从普通纸盒改为定制彩盒；包装成本2元改为5元，请联动维护规格、询价、成本、报价。

1. 点“分析变更影响”，查看每个直接及下游节点。改成本或交期时，也会涉及供应商比较和订单节点。
2. 点“生成联动修订草稿”。旧成果保留；新成本/报价待核实，不能当作已批准最终价。
3. 对每个候选成果编辑并保存**一个新版本**。规格使用 `edits/spec-DE-v2.json`；依据工厂A新版填写包装5元、31天；用核价规则核对9.21美元/件。
4. 在各节点填写处理依据，点选刚保存的新成果，再点“关联已编辑成果”。节点与成果对应如下。
5. 尚未开展的样品、订单和生产阶段，可说明“没有既存下游成果需修改；后续须按彩盒新版建立”，再标记无需修改。已有下游成果时应实际修订，不能套用此结论。
6. 所有候选成果都有新版本、所有节点有处理记录，才激活。仅“记录复核”不算完成。
7. 激活之后选择工厂A彩盒新版重新核价，补齐最新规格/条款，得到9.21美元/件。激活前运行其他任务会改变基线，可能导致当前变更无法激活。

| 节点 | 关联成果 | 本例修改 |
|---|---|---|
| draft_spec_pack / extract_bag_requirements | spec | 彩盒48×33×18cm、CMYK、图稿CB-02 |
| build_supplier_rfq | rfq | 彩盒参数和新版规格引用 |
| normalize_quotes | comparison | 纳入工厂A新版，保留A/B旧报价供比较 |
| calculate_cost | cost | 成本50→53元，固定新版供应商报价ID |
| draft_quotation | quotation | 8.69→9.21美元，生产28→31天，仍待商业批准 |

原价26,070，新价27,630，差额1,560美元。样费60美元、快递35美元另计。对变更节点维护耗时较长时，可用 `demo/advance.py --case de_b --step change` 完成本节；该命令会使用所选变更来件、维护候选版并激活，不会自动批准报价或放行生产。

## 5. Flow C：PO、样品和六项门禁

可直接进入 [03业务资料与审批](http://127.0.0.1:5173/workbench?case=inq_competition_de_c)，或沿01运行到order阶段。

03已收到PO、客户批准邮件、卖方确认、工厂确认、样品检查和模拟付款记录，但这些原件初始只是“已收到”。先点击“检查生产资料门禁”，应显示下面六项缺口，且不能放行。

| 顺序 | 界面操作 | 选择证据/目标 | 核对要点 |
|---|---|---|---|
| 1 | 审批范围“客户规格确认”→记录指定版本批准 | `customer-final-approval.eml`；自动绑定最新spec | BP-DE-3000、彩盒CB-02、3000件、材料/尺寸/LOGO |
| 2 | “记录样品批准” | 同一客户邮件；绑定同一最新spec | SMP-DE-CB02、DEMO-SEAL-02；检查记录自身不是客户批准 |
| 3 | 审批范围“内部报价批准” | 最新quotation，可不选外部证据 | 9.21/件、总额27630、FOB宁波、付款与有效期完整 |
| 4 | “记录双方确认” | PO为 `PO-DE-001-V2.pdf`；买方为客户批准邮件；卖方为 `seller-order-acceptance.eml` | 两方独立证据，指向同一PO |
| 5 | “记录付款保障核验” | `payment-advice.txt` | 说明：模拟核验DEMO-PAY-DE-001，30%定金USD8289，与PO总额USD27630一致 |
| 6 | 审批范围“供应商生产确认” | `supplier-production-confirmation.eml`；自动绑定当前业务版本 | 包装/物料/31天生产条件，仍不保证45天到港 |

再点已有资料包“重新检查”，或“检查生产资料门禁”。六项齐全且没有开放变更时门禁通过，“人工放行”可用。点击后显示“已放行”。

PO总额27,630美元 = 30%定金8,289 + 70%尾款19,341。`payment-advice.txt` 明确为模拟核验材料，不是银行真实水单。PI、生产指令、T&A、QC是可编辑草稿；QC没有伪造“已检验合格”结果。

放行之后不要再生成新规格/新报价来展示历史：新版本需要相应新批准。请从历史成果查看旧版，或新建演练批次。

## 6. 两条异常场景

### 墨西哥：MOQ阻断后恢复

进入04，分析客户原文；选择工厂M，汇率7.2、毛利25、数量300，尝试核价，应提示低于MOQ500。

上传 `mx-quantity-confirmation.eml`，来源角色选客户变更。客户只确认增至600件，未确认样品、订单或付款。将核价数量改成600，发送：

> 客户已确认数量600件帆布袋，请按工厂M报价核价；FOB宁波，不承诺30天到货。

预期成本18.5元、报价3.43美元/件、商品小计2,058美元。生产18天，样品批准和运输计划仍需确认。这里此前没有成功报价，所以直接补充需求后首次核价即可；已存在有效报价再改数量，应走变更维护。

### 英国：澄清与恢复

进入05，在**询盘画板右侧对话**发送“请分析这封询盘，缺少哪些关键需求需要先问客户？”；不要使用业务面板的非交互节点运行按钮。预期Run为`needs_input`。

刷新页面后，待回答任务仍在。对照 `uk-clarification-reply.eml` 回复：

> 客户补充800件电脑包，15.6英寸、深灰色、定制LOGO，伦敦；材料和具体尺寸待确认，仅整理需求，不报价。

预期恢复原Run并生成需求及缺项。没有供应商成本时继续要求报价，应再要求补充供应商原件、汇率和毛利，不能出现虚构单价。

## 10. 新版节点与历史交互

- **直接生成节点**：询盘画布现在始终显示需求、风险、报价和回复节点。点击卡片或节点文档的“依据现有资料生成”，勾选当前原件和Wiki版本，报价时再选择供应商、汇率、毛利和数量。SOP各已实现阶段也有相同入口。生成保留其他节点的当前内容；有开放变更时先完成变更维护。
- **客户来源与背景**：打开“客户原始询盘”即可看到来源渠道、邮箱、官网/LinkedIn示例和待核验事项。5个演示场景分别覆盖Email、独立站、阿里巴巴国际站、Amazon和LinkedIn，全部标记为模拟资料。
- **统一成果入口**：每轮业务版本已保存到数据库，画布只放一个“对话成果汇总”卡片，可切换版本。以前收藏的内容仍保留在汇总页，不再按版本铺满画布。
- **恢复单个节点**：展开左侧“版本记录”，打开旧版，点击“仅恢复需求/风险/报价/回复节点”。新版本成为当前版本，随后可继续编辑；其他节点保持原内容。
- **从旧版继续**：在版本记录中点击“从此版本继续编辑”，复制该版本成为新的当前草稿，记录分叉来源。原历史保留，不会把版本号倒退。
- **恢复单份成果**：在“业务资料与审批”选中历史成果，点击“恢复此成果为新草稿”，然后正常编辑保存。
- **撤销编辑与恢复的区别**：“撤销未提交编辑”只丢弃当前文本草稿的修改；历史恢复会创建新版本。恢复的商业成果需重新审核，不沿用旧批准。

若当前模型服务鉴权或网络失败，演示模式会明确提示使用有限规则抽取。该情况下可以演练来源、核价、版本和门禁，但不代表大模型已成功调用；如需模型抽取，请正确配置 `MODEL_API_KEY`、`MODEL_NAME` 和可选的 `MODEL_BASE_URL`。
