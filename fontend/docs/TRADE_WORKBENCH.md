# TradeWorkbench 前端优化交付说明

日期：2026-10-31（Asia/Shanghai）

依据：TradeWorkbench PRD v1.0

范围：仅前端；没有修改后端或现有 API 合同。

## 已实现

- **任务首页**：开始新工作、继续工作、需要我决定。原有询盘列表移至“全部询盘”，知识、素材、能力及原询盘处理功能保留。新建工作只要求原文或目标，名称与客户可留空。
- **三栏工作区**：左侧资料及成果树，中间编辑画布，右侧执行助手；支持制作、审核、交付三种模式。桌面各面板独立滚动，移动端切换资料、画布、助手。
- **编辑与来源**：成本、汇率、毛利率、数量即时重算；规格字段可编辑，未知值保持待确认。点击来源可回读演示邮件、报价摘录或导入文本。原文件可保存在浏览器并下载。
- **变更闭环**：普通纸盒改为定制彩盒时，预览规格、成本、报价、询价单四项修订；价格缺失或联动项未全部接受时阻止应用。应用后建立新草稿，历史快照保持只读。
- **审核与门禁**：内部报价必须显式审核。再次编辑已审版本时，新建草稿并保留已审历史。PO 数量、单价进行差异比较；缺少客户规格、样品和供应商生产确认时保持生产阻断。
- **交付**：导出 ZIP，包含 3 份 XLSX、4 份 DOCX、未发送的 EML 草稿，以及来源、版本、活动记录的 JSON 快照。支持当前成果打印预览，由浏览器保存 PDF。可按需选择成果。
- **连续工作**：草稿与版本保存在 localStorage，导入原文件保存在 IndexedDB，按用户、工作空间、Case 隔离；回到首页显示最新版本、报价和下一步。存储失败会提示，不报告保存成功。
- **视觉与加载**：接入 Navowork 已确认的手绘 NAW 图标与蓝、黑、白品牌体系，支持浅色、深色及跟随系统；详见 [品牌主题接入说明](./BRAND_THEME.md)。工作区和资源页面按需加载，提供窄屏适配、键盘焦点、模态框关闭及减少动态效果支持。

## 演示路径

1. 进入演示工作空间，点击“完成定制背包报价”。
2. 成本 ¥44 + ¥2 + ¥4，汇率 7.20，目标毛利率 20%，数量 3,000：单价 **$8.69**，总价 **$26,070.00**。
3. 点击“改为定制彩盒”，查看四份成果差异；取消价格证据勾选，验证缺少价格时无法应用。
4. 接受关联变更：包装成本 ¥5，总成本 ¥53，新单价 **$9.21**，总价 **$27,630.00**；版本记录中仍可回看原 V1。
5. 打开客户报价单并完成内部审核；进入生产资料包，查看独立批准要求以及 PO 差异。
6. 进入“交付”，查看收件人、附件清单与邮件内容，下载草稿文件包。

## 与真实系统的边界

- 新背包工作区使用 PRD 的合成演示数据，页面明确标注。现有询盘仍沿用原 API 与 Mock/真实服务切换。
- 助手运行浏览器内预设流程，支持暂停与继续。自由目标只记录，不模拟模型理解、自动提取或真实执行。
- 文本可直接预览；PDF、Excel、图片保留原文件，自动解析和来源坐标提取需接后端。
- 金额计算、版本、校验、导出已在前端实现；浏览器保存不是团队服务端存储。清除浏览器数据会删除本地草稿。
- 当前新工作区支持固定德国背包演示 Case。通用 Job、任意 Case 成果管理及服务端审批审计需后续对接。
- 内部报价审核是演示操作，不能代替组织权限校验。生产没有正式放行入口，导出始终标为草稿。没有发送邮件、下单或宣布开工。
- XLSX 包含结构化字段和当前计算结果，Word 使用基础排版；企业模板、价格规则及原生 Excel 公式可在后端文件服务中深化。PDF 由浏览器打印保存。

## 验证结果

- 生产构建与 TypeScript 检查通过；入口 JavaScript 小于 Vite 的 500 kB 警告阈值。
- 28 项单元测试通过：现有 API、定价、非法输入、版本保护、PO 差异及 ZIP/Office 结构。
- 27 项端到端测试通过：原询盘/资源/草稿流程和新增工作区。首页版本联动调整后，7 项新增流程再次通过。
- 使用 openpyxl 实际打开 3 份 XLSX，使用 python-docx 实际打开 4 份 DOCX，均可正常读取。
- 1440px 桌面及 390px 移动端已截图检查，无页面横向溢出。
- Prettier 与 git diff --check 通过。
